# Worklog — 2026-07-09

## 1. เชื่อมระบบ Organizer / Admin / Runner ให้คุยกันจริง

### เดิมเป็นยังไง
ที่ผ่านมาทั้ง 3 ฝั่งเป็น "เกาะแยกกัน 3 เกาะ" — Organizer สร้างงาน แต่ Admin ไม่เห็น, Admin กดอนุมัติ แต่ Organizer ก็ไม่รู้ ทุกอย่างเป็นหน้าจอเดโมที่ไม่ต่อกัน

### เปลี่ยนเป็น
ทำให้ทั้งแพลตฟอร์มใช้ข้อมูลงานชุดเดียวกัน กด action ฝั่งไหนอีกฝั่งเห็นผลทันที และข้อมูลไม่หายเมื่อรีเฟรชหน้า (จำสถานะไว้ในเครื่อง)

---

## 2. Flow อนุมัติงานครบวงจร (Organizer → Admin → Go Live)

### เหตุผล
หัวใจที่ขาดคือ "Organizer สร้างงาน แล้ว Admin อนุมัติให้ขึ้นจริง" — เดิมกด Submit แล้วไม่มีอะไรเกิดขึ้น

### สิ่งที่เปลี่ยน
- **Organizer กด Submit** → งานเข้าคิว "รอตรวจสอบ" ของ Admin จริง พร้อมชื่อผู้จัดเจ้าของงาน
- **Admin ตรวจแล้วเลือกได้ 2 ทาง:**
  - **อนุมัติ** → งานไปสถานะ "รออนุมัติขึ้นระบบ"
  - **ตีกลับ (Request Changes)** → ใส่เหตุผลได้ และ **เหตุผลจะเด้งกลับไปให้ Organizer เห็น** ว่าต้องแก้อะไร แล้วแก้ส่งใหม่ได้
- สถานะทั้งหมดสะท้อนกลับที่หน้า Dashboard ของ Organizer แบบเรียลไทม์ (แท็บใหม่: All / Live / In Progress / Drafts / Cancelled)

## 3. Admin เป็นคนกดยืนยันขั้นสุดท้ายก่อนงานขึ้นจริง

### เหตุผล
เดิมงานที่ผ่านอนุมัติแล้ว "ค้าง" ไปต่อไม่ได้ ไม่มีปุ่มไหนทำให้ขึ้นจริง

### สิ่งที่เปลี่ยน
- เพิ่มแท็บ **"Ready to Publish"** ในหน้า Admin — งานที่อนุมัติแล้วมารออยู่ตรงนี้
- Admin กดปุ่ม **"Publish · Go Live"** เอง งานถึงจะขึ้นสถานะ Live (เป็นด่านสุดท้ายที่แพลตฟอร์มคุมเอง)

---

## 4. เปลี่ยนโมเดลรายได้เป็น "ค่าคอมมิชชั่นต่อยอดสมัคร"

### เหตุผล
เดิมระบบคิดรายได้แพลตฟอร์มเป็นค่าธรรมเนียมเหมารายงาน (1,500฿/งาน) ซึ่งไม่ตรงกับธุรกิจงานวิ่งจริง ที่แพลตฟอร์มระดับโลกเก็บเป็น % ต่อยอดขายบัตร

### สิ่งที่เปลี่ยน
- แพลตฟอร์มเก็บรายได้เป็น **% ต่อยอดสมัคร** (ตั้งค่าเริ่มต้น 6%) หักตอนจ่ายเงินคืนผู้จัด
- หน้า Settings ปรับเป็นตั้งค่า: อัตราคอมมิชชั่นมาตรฐาน, อัตราสำหรับ VIP, และระยะเวลากันเงินหลังจบงาน
- หน้า Dashboard ของ Admin โชว์ "รายได้แพลตฟอร์ม" เป็นค่าคอมมิชชั่นที่เก็บได้จริง

---

## 5. ระบบจ่ายเงินคืนผู้จัด (Payout) + เงินพักในระบบ (Escrow)

### เหตุผล
ธุรกิจจริงเงินค่าสมัครวิ่งเข้าแพลตฟอร์มก่อน แล้วแพลตฟอร์มค่อยโอนคืนผู้จัดหลังงานจบ — ส่วนนี้เดิมไม่มีเลย

### สิ่งที่เปลี่ยน หน้า Financials ทำใหม่ทั้งหน้า มี:
- **สรุปเงินรวม 4 ก้อน:** เงินพักในระบบ (escrow), เงินพร้อมโอน, โอนไปแล้ว, ค่าคอมที่แพลตฟอร์มได้
- **คิวจ่ายเงิน (Payout Queue):** งานที่จบแล้ว โชว์ยอดขาย − เงินคืน − ค่าคอม = **ยอดสุทธิที่ต้องโอนผู้จัด** พร้อมเลขบัญชีรับเงิน และปุ่ม "ยืนยันโอนแล้ว"
- **ประวัติการโอน** และ **บันทึกการคืนเงิน (Refund ledger)**

## 6. หน้าตรวจงานเต็ม (Event Review) สำหรับ Admin

### เหตุผล
เดิม Admin กดอนุมัติโดยเห็นแค่ชื่องาน+วันที่ = อนุมัติแบบตาบอด ซึ่งเสี่ยงเรื่องความปลอดภัยนักวิ่ง

### สิ่งที่เปลี่ยน
กด "Review" ในคิวแล้วเข้า **หน้าตรวจงานเต็มหน้า** (แยกออกมาเลย ไม่ใช่ป๊อปอัพเล็ก) โชว์:
- **ข้อมูลงานครบ:** คำอธิบาย, ทุกประเภทการแข่ง พร้อมระยะ/ความชัน/ภูมิประเทศ/เวลาสตาร์ท-ตัดตัว, **อุปกรณ์บังคับ** และ **ตารางจุดเช็คพอยต์** (จุดไหนมีน้ำ/อาหาร/แพทย์) — ข้อมูลด้านความปลอดภัยที่ผู้รีวิวต้องเห็น, และราคาบัตรแยกใบ
- **แถบข้อมูล Organizer:** ชื่อผู้ติดต่อ/อีเมล/เบอร์, ประเภทบัญชี (Standard/VIP), จำนวนงานที่เคยจัด, สถานะบัญชี — ให้ Admin ประเมินความน่าเชื่อถือของผู้จัดที่ตัวเองดูแล
- ปุ่มตัดสินใจ (Approve / Request Changes) ตรึงอยู่ด้านล่าง
- ถ้างานไม่มีข้อมูลประเภทการแข่ง ระบบเตือนให้พิจารณาตีกลับก่อนอนุมัติ

> หมายเหตุ: ยังมีของด้านความปลอดภัยที่ระบบ**ยังไม่มีช่องเก็บ** (ไฟล์เส้นทาง GPX, นโยบายคืนเงิน, แผนการแพทย์/ใบอนุญาต) — เก็บไว้เป็น phase เพิ่ม field ทีหลัง

## 7. ระบบประเภทผู้จัด (Standard / VIP)

### เหตุผล
รองรับนโยบายที่ผู้จัดบางประเภทไม่ต้องเสียค่าคอมมิชชั่น

### สิ่งที่เปลี่ยน
- ตอน Admin สร้างบัญชีผู้จัดใหม่ เลือกประเภทได้: **Standard** (เสียค่าคอม) หรือ **VIP** (ยกเว้นค่าคอม 0%)
- หน้ารายชื่อผู้จัดโชว์ป้ายประเภทกำกับ และระบบคิดค่าคอมให้อัตโนมัติตามประเภท

## 8. จัดข้อมูลตัวอย่างให้สมจริง + 2 ฝั่งตรงกัน

### เหตุผล
ข้อมูลตัวอย่างเดิมไม่สมจริง 2 จุด: (1) งานฝั่ง Admin หลายตัว "ไม่มีประเภทการแข่งเลย" ซึ่งเกิดขึ้นจริงไม่ได้ (Organizer submit งานแบบไม่มีประเภทการแข่งไม่ได้อยู่แล้ว) (2) งานที่ Organizer เห็นกับที่ Admin เห็นเป็นคนละชุด ทำให้ดูเหมือนข้อมูลไม่เชื่อมกัน

### สิ่งที่เปลี่ยน
- **ทุกงานมีประเภทการแข่งจริงทั้งหมด** — ไม่มี case ที่เป็นไปไม่ได้อีก
- **จัดให้ผู้จัดหลัก (Trail Events Co.) มีงานครบทุกสถานะ** (Live / รอตรวจ / รออนุมัติขึ้นระบบ / ถูกตีกลับ / ร่าง / รอยกเลิก) → หน้า Dashboard ของ Organizer เห็นงานครบวงจร และ **ตรงกับที่ Admin เห็นทุกงาน**
- คงผู้จัดเจ้าอื่นไว้ 3 เจ้า (มีประเภทการแข่งจริง) เพื่อให้ Admin เห็นภาพ multi-tenant + มีตัวอย่างงานรอยกเลิก/รอจ่ายเงินจากเจ้าอื่น

## 9. หน้า Admin Review — เติมข้อมูลให้ครบ (ทุก field ที่ระบบมี)

### เหตุผล
หน้าตรวจงานยังไม่ได้โชว์ข้อมูลบางอย่างที่ระบบเก็บไว้แล้ว

### สิ่งที่เพิ่ม
- **ช่วงวันงาน** (วันเริ่ม–วันจบ) รองรับงานหลายวัน
- **พื้นที่รูปปกงาน** (ถ้ายังไม่อัปโหลดจะบอกชัดว่า "ยังไม่มีรูปปก" — ผู้รีวิวเห็นได้)
- **พิกัดแผนที่** + ลิงก์เปิด Google Maps
- **คำอธิบายภาษาไทย** (คู่กับภาษาอังกฤษ)
- **วันแข่งของแต่ละประเภท** + พิกัดจุดสตาร์ท
- **ลิงก์โซเชียล** (Facebook / Instagram / เว็บไซต์)

> ยังเหลือกลุ่มที่ระบบยังไม่มีช่องเก็บ (ไฟล์เส้นทาง GPX, นโยบายคืนเงิน, แผนความปลอดภัย/การแพทย์, ใบอนุญาต) — เก็บเป็น phase เพิ่ม field ทีหลัง

## 10. Audit ข้อมูล + เอา field ที่ Organizer กรอกไม่ได้จริงออก

### เหตุผล
ตรวจพบว่าหน้า Admin Review โชว์ข้อมูลบางอย่างที่ **Organizer ไม่มีช่องกรอกจริงตอนสร้าง Event** — คือหยิบจากข้อมูลตัวอย่างมาโชว์เอง ไม่ได้อิงสิ่งที่ผู้จัดกรอก

### ผลตรวจ (เทียบกับช่องกรอกจริงใน Wizard)
- **อุปกรณ์บังคับ (Mandatory gear)** และ **จุดเช็คพอยต์ (Checkpoints)** → Wizard **ไม่มีช่องให้กรอกเลย** = ข้อมูลถูกสร้างขึ้นมาเอง
- **รูปปก (Cover photo)** → อัปโหลดจริงยังไม่ได้ (ปุ่มยังไม่ทำงาน)
- ที่เหลือ (ชื่อ/จังหวัด/วันที่/พิกัด/คำอธิบาย/โซเชียล + ระยะ/ความชัน/terrain/ITRA/UTMB/cut-off/บัตร) → กรอกได้จริง โชว์ถูกต้อง

### สิ่งที่เปลี่ยน (ตามที่ตกลงกับ PO)
- **เอา Mandatory gear + Checkpoints ออกทั้งระบบ** (PO ยืนยันว่าไม่ต้องมี) — ทั้งหน้า Review, หน้า preview งาน, และตัวกรอกใน Wizard
- **คงรูปปกไว้** (แสดงพื้นที่รูป + บอก "ยังไม่มีรูป" ถ้ายังไม่อัปโหลด) — เป็นฟีเจอร์ที่ตั้งใจให้มี แค่ระบบอัปโหลดยังไม่ได้ทำ
- **แก้ความไม่สอดคล้อง Capacity vs Seats** → ตอนนี้ **Capacity = ผลรวมจำนวนบัตรทุกประเภทเสมอ** (สรุปจากของจริงที่กรอก) ไม่มีทางขัดกันอีก หน้า Review โชว์ Capacity + Sold (ตัดตัวเลขซ้ำออก)

## 11. ปิด loop การตีกลับงาน + แก้ UX ฝั่ง Organizer

### เหตุผล
flow ตีกลับเดิม "เดินได้" แต่ยังไม่สมเหตุสมผลในมุมผู้จัด: ถูกตีกลับแล้ว **มองไม่เห็นเหตุผลว่าต้องแก้อะไร**, งานที่ต้องตัวเองแก้ปนกับงานที่รอแพลตฟอร์ม, และป้ายบางสถานะมองไม่เห็นบนการ์ด

### สิ่งที่เปลี่ยน
- **แสดงเหตุผลที่ถูกตีกลับให้ผู้จัดเห็น** — ทั้งบนการ์ดงานใน Dashboard และเป็นแถบเตือนในหน้าแก้ไข (Wizard) พร้อมข้อความ "แก้แล้วส่งใหม่"
- **ปุ่มเปลี่ยนเป็น "Resubmit for Review"** เมื่อแก้งานที่ถูกตีกลับ + **ล้างเหตุผลเก่าทิ้งอัตโนมัติ** เมื่อส่งใหม่
- **แยกแท็บ "Action Needed"** (งานที่ผู้จัดต้องลงมือแก้) ออกจาก **"In Review"** (งานที่รอแพลตฟอร์มตรวจ/ขึ้นระบบ) พร้อม**ตัวเลขแจ้งเตือน**บนแท็บเมื่อมีงานค้าง
- **แก้สีป้ายสถานะบนการ์ด** — "Approved · Pending Go-Live" และ "Changes Requested" เดิมพื้นหลังโปร่งแสง มองไม่เห็นบนรูป → เปลี่ยนเป็นพื้นทึบเต็มสีเหมือนสถานะอื่น (Live/Pending Review)
